### Real bug: assignment task header layout (items 28 & 29)
I did not just re-style this — I built a standalone static HTML page
reproducing the exact header markup `assignmentTopBarHtml()` generates
(long title, streak chip, running focus timer, task timer, 20-question
progress strip) against your real `styles.css`, and rendered it in a real
browser at 1400px, 1280px, 1049px, 720px, and 390px widths. **Confirmed two
real, reproducible bugs**, not stylistic guesses:
1. `.assignment-top-status` (the container holding the streak chip, focus
   timer, task timer and progress dots) had `flex-wrap`/`justify-content`
   CSS properties set on it but was **never actually given `display:flex`**
   anywhere in the stylesheet — so those properties were no-ops, the
   container behaved as a plain block, and the progress-dots strip (itself
   a block-level flex container) always dropped to its own line below the
   timers instead of sharing the row, even on a 1400px-wide screen.
2. `.assignment-progress-wrap>strong` (the "N / total" counter) had a
   competing CSS rule setting `min-width:auto` with no `white-space`
   control, so at constrained widths the browser wrapped "1 / 20" onto two
   lines inside its own pill — the exact "1/20 clipping" you described.
- **Fixed**: added `display:flex` (+ `align-items:center`) to
  `.assignment-top-status`, `flex-shrink:0` on the timer/streak/counter
  elements so they never compress, and `white-space:nowrap` on the counter
  text. Re-tested all 5 widths after the fix — single clean row everywhere
  from 1049px up, and a sensible 2-row wrap on genuinely narrow phones
  (390px) with nothing clipped or overlapping.

### Real bug: background picture theme never applied (item 16)
Reproduced with a static test page (real `styles.css`, a bright test image
set via `document.documentElement.style.setProperty('--mx-user-bg', ...)`
exactly like `applyThemePreferences()` does) — the picture never showed,
confirming your report. **Root cause**: `body .relaxed-main-shell` (a
higher-specificity selector, because it includes the `body` type selector)
had a hardcoded `background:#f4f5f8 !important`, which beats the
plain-class `.relaxed-main-shell{background:var(--mx-user-bg)...!important}`
rule regardless of source order, since both are `!important` and CSS
specificity — not order — decides ties between two `!important` rules of
different specificity. Every custom colour, preset, and uploaded picture
was silently overridden across the entire main content area.
- **Fixed**: `body .relaxed-main-shell`'s background now uses
  `var(--mx-user-bg)` (keeping its two decorative radial-gradient accents
  layered on top) instead of the hardcoded colour.
- **Verified**: re-ran the same static reproduction after the fix — the
  test picture now genuinely renders behind the content.

### Coordinate grid had no axis labels (item 7)

### Indices formatting bug (part of item 6)
`mathHtml()`'s exponent-to-`<sup>` converter only matched a single digit
run or a single letter inside `^{...}` — anything else (a fractional index
like `x^{-1/2}`, a multi-character exponent like `x^{2n}` or `a^{n+1}`)
partially matched, leaving a mangled stray `}` in the rendered text (e.g.
`x<sup>-1</sup>/2}`). This is a real curriculum topic (NSW Year 9 "6H
Fractional indices and surds") so it would have shown broken text to real
students. **Fixed**: the braced form now matches any content inside
`^{...}` generically, with the old single-digit/single-letter patterns kept
as fallback for un-braced exponents (`x^2`, `a^n`). Verified with 10 test
cases in Node including fractional, negative, decimal, and multi-character
exponents — all render correctly now.
- **Not done**: a full visual pass across all 12 question-type renderers
  (numeric/fraction/algebra/MCQ/coordinate/graph/written/multi-part/
  matching/drag-drop/number-line) beyond this specific, confirmed indices
  bug. I did not find other obvious formatting breaks while reading the
  code, but I did not visually render all 12 types with real content the
  way I did for the header/theme/graph bugs above, so I'm not claiming a
  clean bill of health there.

### Student Goals now auto-track (item 17)

actually changed. The manual "+1" button now only appears on `custom`
goals — auto-tracked goals show a "✓ Complete" chip instead once they hit
target.
