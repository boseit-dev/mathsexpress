# MathsExpress v11.5.18 — Stakeholder Feedback Fixes

Rebases the repository onto the deployed v11.5.17 build and re-applies the
fixes previously merged as #1 and #2, which had been written against v11.5.13.

## Repository baseline

- The repo was four releases behind production: it held v11.5.13 while the live
  Worker served v11.5.17, so a deploy from `main` would have rolled the site
  back and removed the Supabase proxy added in v11.5.15.
- Every file now matches the deployed v11.5.17 build byte for byte, except the
  five changed deliberately below. Verified against the running site.
- The v11.5.14–v11.5.17 release notes and the five upstream test files
  (login fallback, login release, active project, proxy, network fallback) are
  now in the repository for the first time.

## Fixes re-applied from #1

- Tour launch button is removed once that page's walkthrough is complete.
- Joining with an unknown class code now fails instead of reporting success.
- Task Library button no longer renders inside the Task Library tab.
- Curriculum list trimmed to the Australian and Cambridge systems.
- Staff & leadership cards no longer stretch to the grid row height.
- Class join code and school identifier relabelled so only one reads as a code
  students enter.

## Fixes re-applied from #2

- Loading modals that never resolve are replaced with a dismissible error,
  via a watchdog in `openSimpleModal` plus direct handling in ten loaders.
- Integration 404 message names the remedy rather than failing generically.
- Adds `supabase/migrations/20260929_01_class_skill_focus.sql`, which creates
  the two Skills Focus RPCs the client has been calling without them existing.

## Cache busting

`deploy-app.js`, `deploy-core-1.js` and `styles.css` all changed in this
release, so their `?v=` query strings move to `11.5.18` and the service-worker
cache becomes `mathsexpress-v11-5-18`. Without this, returning browsers would
keep serving the cached v11.5.17 bundles and none of the fixes would appear.
`tests/login-release.test.cjs` is updated to pin the new release.

## Not addressed here

- `public/app.html` contains an inline startup fail-safe that the
  `script-src` policy in `public/_headers` blocks. This already happens on
  production and is unrelated to this release, but it means the blank-page
  safety net does not run.
- `sitemap.xml` and `robots.txt` still advertise `mathsexpress.netlify.app`,
  which no longer resolves.
