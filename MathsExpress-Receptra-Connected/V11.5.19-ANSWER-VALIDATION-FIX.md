# MathsExpress v11.5.19 — Answer Validation Fix

Fixes the reported "you can type anything in, and it will say 100% accuracy"
behaviour in Discovery Check-Ins, and the same flaw in Fix Mode.

## Root cause

`symbolicEquivalent()` returns a result object, `{equivalent, reason}`. Two
grading call sites used that return value directly as a boolean:

```js
validateAnswer(...).correct === true || symbolicEquivalent(actual, answer)
```

An object is always truthy in JavaScript, so as soon as `validateAnswer`
judged an answer wrong, the `||` fell through to a truthy object and the answer
was counted correct. Every response scored as correct regardless of content.

`validateAnswer` itself was never at fault — it compares numerics with
tolerance, matches multiple-choice exactly, and normalises expressions.

## Affected

- **Discovery Check-In and Topic Readiness** (`handleV7Submit`) — produced 100%
  accuracy for any input, and wrote that evidence to
  `mathsexpress_record_diagnostic_response` and the IRT growth estimate.
- **Fix Mode** (`checkFixAnswer`) — not in the original report, and worse: any
  text marked a correction as valid and called
  `mathsexpress_complete_fix_item`, awarding the recovered marks back. Typing a
  single character restored full marks on a wrong answer.

Both now read `.equivalent === true`.

The `||` fallback is kept rather than removed. It is what correctly accepts
`1/2` on the probability item, whose answer is a fraction stored on a question
typed `numeric`, so `validateAnswer` alone cannot grade it.

## Typed-character restriction

The project already had the machinery for this — `mathAnswerInputAttrs()` marks
a field with the letters and units its own question allows, and a delegated
input handler runs `sanitizeMathAnswerInput()` to strip anything else. It was
applied to the main lesson inputs but not to several graded fields. Now also
applied to:

- Discovery Check-In and Topic Readiness question fields
- the Fix Mode correction field
- the Global Challenge answer field

Allowed letters are derived from each question's own prompt and answer, so a
question about `x` permits `x` and nothing else.

Two inputs are deliberately left unrestricted: `profile-name` is a display name,
and `handwriting-typed-fallback` has no question context where it is rendered.

## Verification

`tests/answer-validation.test.cjs` covers the result-object contract, a
regression guard against using it as a boolean, the input-restriction
attributes, and an end-to-end reproduction of the grading expression across all
Discovery Check-In questions: arbitrary text and wrong numbers are rejected on
every question, and every correct answer is still accepted. The regression guard
was confirmed to fail against the pre-fix code.
