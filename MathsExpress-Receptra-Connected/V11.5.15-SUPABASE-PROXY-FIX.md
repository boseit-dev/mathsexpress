# MathsExpress v11.5.15 — Supabase connection fix

## Root cause addressed
The browser was still throwing `Failed to fetch` while trying to reach the Supabase project directly. The previous v11.5.14 fallback still depended on a second direct browser-to-Supabase request, so it could fail for the same network reason.

## Changes
- Added a same-origin Cloudflare Worker proxy at `/api/supabase/*` for the MathsExpress Supabase project's HTTP APIs.
- The Supabase JS client now routes Auth, REST/RPC, Storage and Edge Function HTTP requests through that same-origin proxy.
- Login Edge Function calls now use the proxy.
- Email login falls back to normal Supabase password auth for missing or 5xx login-function responses.
- Signup Edge Function calls now use the proxy as well.
- Bumped the auth bundle and service-worker cache to v11.5.15 so browsers do not keep the previous login code.

## Verification
- 9/9 automated Node tests passed.
- `deploy-core-1.js`, `worker.js`, and `service-worker.js` passed JavaScript syntax checks.
- Proxy tests verify that Supabase Auth URLs are rewritten to same-origin and that the Worker forwards them to the configured Supabase project.

The test environment cannot make a live network request to the real Supabase project, so the final live login must be checked after deploying this Worker.
