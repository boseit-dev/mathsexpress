# MathsExpress v11.5.16 — login network fallback fix

## What changed
- Supabase requests still try the same-origin Cloudflare Worker proxy first.
- If the proxy request itself fails at network level, MathsExpress retries the trusted Supabase project directly.
- If the proxy route is missing or returns a gateway/server availability response (404/405/501/502/503/504), MathsExpress also retries the trusted Supabase project directly.
- Local `file://` previews no longer try the nonexistent `/api/supabase/*` route.
- If both proxy and direct network paths fail, login reports a clear deployment/network message instead of a raw `Failed to fetch`.
- Bumped auth/config/loader cache versions and the service-worker cache to v11.5.16.

## Why
The v11.5.15 code made the Cloudflare proxy the only transport for Supabase requests. A missing/unreachable proxy therefore still produced the exact browser `Failed to fetch` error shown in the login screen. v11.5.16 makes the transport resilient to either path being unavailable.
