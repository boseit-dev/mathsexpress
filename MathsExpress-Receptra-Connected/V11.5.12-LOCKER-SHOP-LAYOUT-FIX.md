# MathsExpress v11.5.12 — Locker & Shop layout fix

You reported the character customisation (Locker) page was "all messed up" and
sent screenshots. I reproduced both pages in a real browser using the actual
app code and CSS before and after each fix, rather than guessing from reading
the CSS alone.

## Bug 1 — Locker page: crushed customisation panel + huge empty gap
**Root cause**: `.locker-layout` forced its first column to a fixed `340px`,
and the Character Appearance card (with its own internal two-column layout
needing ~600px+ for the live preview + colour/style controls) was nested
inside that 340px column. The controls were being crushed into a sliver of
space, which is why labels like "Skin colour" and "Second top colour" were
wrapping into unreadable fragments ("S c", "S to c") and a button was cut off
at the edge. Meanwhile the right-hand "Owned cosmetics" column had all the
leftover space, showing one small card in a huge empty area.

**Fixed**: restructured the Locker page — the character preview and "Owned
cosmetics" now sit side by side in a top row (each getting a sensible,
proportional width), and the Character Appearance card now spans the full
page width below that, so its own two-column layout has the room it was
always designed for. Verified in a real browser at 1280px and mobile (375px)
— all labels fully readable, no cut-off buttons, no dead space.

## Bug 2 — Shop page: cards cut off at the right edge
**Root cause**: `.shop-grid` was hard-coded to always show exactly 3 columns
(`repeat(3, minmax(0,1fr))`), with old breakpoint overrides (from a previous,
different sidebar-based layout) dropping to 2 then 1 column only at 1100px
and 820px. On the app's actual current width (content capped at ~1220px,
minus the ~360px live-preview panel), 3 fixed columns didn't leave enough
room per card, which is why "Football Pro", "Galaxy Genius" and others were
showing cut off.

**Fixed**: replaced the rigid fixed-column grid with
`repeat(auto-fill, minmax(260px, 1fr))` and removed the now-redundant old
breakpoint overrides. The grid now always picks however many columns
actually fit cleanly — 2 roomy columns at typical desktop widths, more on
very wide screens, 1 on mobile — and can never cut a card off regardless of
window size. Verified in a real browser at 1280px, 1600px, and mobile
(375px).

Both fixes were verified by rendering the real `renderLocker()`/`renderShop()`
output against the real `styles.css` in an actual browser and taking
screenshots before and after, not just by reading the CSS.
